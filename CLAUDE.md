# GDM World

Static Preact + TypeScript + Vite app. Use Node 24. Run the local tsc, ESLint, Vitest and Vite binaries as listed in README. Vitest uses happy-dom and disables Node's experimental Web Storage globals.

## Data and invariants

- `src/lib/wires.ts` owns the versioned schemas and limits. All outgoing wires pass through `makeWire`, which signs every field with mistai's canonical serializer and includes a currently valid delegation when available. Legacy code-unit ordering produces the same bytes for existing schema keys. `wireSign.ts` verifies Ed25519 synchronously via noble. All received records reach the store through schema and signature checks, including OPFS, sync replies, and vault restore.
- Projects may include a primary language (`lang`) and up to two `translations` for title, summary, and description. Legacy records and local drafts still parse without these fields.
- The log is an append-only union keyed by signature. Verified but currently ineffective records can participate when the rest of the signed history arrives. `authz.ts` derives access from the current winning grants rooted in configuration. The issuer's resolved person DID determines current admin eligibility and root priority. Grants and revocations target person DIDs. Circular authorization oscillations fail closed for the unstable DIDs.
- `catalogStore.ts` projects owner, LWW edits, and tombstones from the union. Revision 1 claims the project UUID, and conflicting claims sort by creation time, person DID, and signing leaf DID. Edits preserve the owner's creation timestamp and wait for the claim during replay. Historical eligibility at the signed timestamp keeps an old claim or tombstone anchored when roles change. The current role controls project visibility. This uses replayable signed evidence and the client's wall clock, with millisecond timestamps.
- `mirror.ts` unions both local replicas and serializes read-merge-write with Web Locks when available. A failed read leaves that replica untouched. BroadcastChannel triggers reads in sibling tabs. Preserve tombstones and superseded signed records during merge.
- Approval requests and signed rejects use a separate store. Requests are deduplicated and rate-limited by person DID. The UI exposes them to admins. The room and its request traffic are public. Drafts, the display name preference, and theme are saved in browser-local storage.
- Signed `gdmw:profile` records share a trimmed display name in the catalog. Profiles use the resolved person DID and the greatest `updatedAt`, breaking ties by signature. Current members and admins see their profile names used across the catalog, with their latest retained approval request as a fallback. The signed union retains profiles across role changes.
- Signed `gdmw:stats` records use UTC days and project bitmasks for impressions (1), detail opens (2), and primary link clicks (4). Each resolved person contributes one flag per project and day. The store unions flags across leaves and keeps the newest signed evidence for each flag by `updatedAt`, then signature. Stats use a separate OPFS/localStorage mirror and dated P2P digests, with 90 UTC days of retention. Every viewer can contribute, so additional DIDs can inflate the counts. Aggregate counts exclude the project's author and appear in the detail dialog for authors and admins.

## DID delegation

- `fromId` is the leaf DID that signed the whole wire, including the optional `delegation`. After validating the outer signature, `wires.ts` resolves and caches the verified record's person DID for `personId`. A valid certificate resolves to the mistl root. A missing, malformed, expired-at-signing, or leaf-mismatched certificate resolves to the leaf.
- Use the record's signed timestamp to verify its delegation. Upserts use `updatedAt`, including edits by a different leaf. Vault configs with delegation carry a signed `configuredAt`. Legacy configs resolve to the signing leaf. Ephemeral sync envelopes use receipt time and confer no authority over the records they carry. All timestamped wire types reject timestamps more than five minutes ahead of the receiver. Mistvault parses synchronously, so `delegation.ts` uses mistai's signing payload and DID decoder with the app's synchronous verifier. Cross-tests compare the result with mistai's async verifier.
- History remains attributable to the same person after the certificate expires. A leaf holder can backdate new records into an old delegation window, including its five-minute skew, because the timestamp is signed by that leaf and there is no independent timestamp or delegation revocation list. The app still evaluates the resolved person's applicable catalog role. Earlier leaf-only records and approvals keep their original DID during pairing and unpairing.
- `didPairing.ts` uses mistai's path A pairing, path B JSON verification, and shared `tc-shared-did-delegation-v1` storage. The runtime subscribes to storage changes and updates the local person DID and seven-day expiry warning. Both pairing and vault transport use room handles over the same MistNode singleton.
- `package.json` declares the GitHub mistai dependency. `package-lock.json` pins mistai 0.10.4 at the same revision as tc-news (`ad0bffb63f6766f0860ca6e8e739d38e21fbe8ce`). When fetching GitHub dependencies is unavailable, copy a built `@tik-choco/mistai` (e.g. from a sibling tc-news checkout's `node_modules`) into this checkout's `node_modules/@tik-choco/mistai` and run `npm install` against the lockfile. This checkout was verified using that copy with Git disabled for npm.

## Rooms and escrow

- `mistClient.ts` owns one MistNode and fans out callbacks. Match the event room exactly, then check the signed envelope room. Acquire each room via `joinRoomAsync`; release the same room with `leaveRoom(roomId)`. Lease counts keep shared consumers from disconnecting each other.
- The global swarm room, public catalog scope, and mistl provider room are three distinct IDs. Share the canonical `mistSignaling.ts` byte-for-byte with tc-chat. Reliable sync messages contain bounded batches of signature keys or records. Periodic digests repair gaps and share vault restores with peers.
- The full signed catalog history (projects, tombstones, approvals, revocations, and profiles) uses one shared distributed vault on mistl. Automatic mode derives the escrow room from the app ID and fixed public scope ID. Copy the resulting room from **設定 → 高度な設定 → 分散保管庫** and register it with `mistl escrow rooms add <room>`.
- The lowest live node ID writes checkpoints. Only current admins, including paired leaves of root admins, can change the room or mode. Peers adopt settings after verifying a signed wire for the global room and checking the resolved person's current admin role. The vault's config `by` stays the signing leaf for revision and transport semantics. A previously adopted setting persists locally until a newer setting wins. The public scope permits third-party checkpoints. Every restored record passes the same checks as a live record.
- The published mistvault dependency predates the scoped API; the aliases in Vite and tsconfig point to the supplied source in `vendor/mistvault`. Keep both mappings aligned. Revisit them when the pinned upstream version ships `createScopeVault` and `ScopeVaultPanel`.
- Markdown renders text and safe VNodes from the vendored renderer. Thumbnails use blob URLs from validated raster bytes, direct HTTPS image URLs, or automatic page metadata (`og:image` and related tags) with a WordPress mshots fallback. Asset paths are relative to Vite's build base and routes use the hash.
- Deploy: `just deploy` uploads changed files in dist/ over FTPS (scripts/ftps-upload.mjs, copied from tc-game) to https://gdm.tik-choco.com/worlds/. Base path defaults to /worlds/ (VITE_BASE_PATH); canonical/og URLs in index.html are absolute to that origin.
